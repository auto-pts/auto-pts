BIP Service (ID 33)
===================

Commands and responses:

        Opcode 0x00 - Error response

        Opcode 0x01 - Read Supported Commands command/response

                Controller Index:       <non-controller>
                Command parameters:     <none>
                Response parameters:    <supported commands> (variable)

                Each bit in response is a flag indicating if command with
                opcode matching bit number is supported. Bit set to 1 means
                that command is supported. Bit 0 is reserved and shall always
                be set to 0. If specific bit is not present in response (less
                than required bytes received) it shall be assumed that command
                is not supported.

                In case of an error, the error response will be returned.

        Opcode 0x03 - Connect RFCOMM command

                Controller Index:       <controller id>
                Command parameters:     Address_Type (1 octet)
                                        Address (6 octets)
                                        Channel (1 octet)
                Response parameters:    <none>

                This command creates the RFCOMM transport that will carry the
                BIP OBEX session. Address is the peer BD_ADDR and Channel is
                the RFCOMM server channel number, typically obtained from the
                SDP Discover command (0x09) or from a PIXIT. RFCOMM Connected
                Event (0x80) (or RFCOMM Disconnected Event (0x81) in case of an
                error) shall be expected after issuing this command.

                In case of an error, the error response will be returned.

        Opcode 0x04 - Disconnect RFCOMM command

                Controller Index:       <controller id>
                Command parameters:     Address_Type (1 octet)
                                        Address (6 octets)
                Response parameters:    <none>

                This command closes the RFCOMM transport identified by Address
                (the peer BD_ADDR). RFCOMM Disconnected Event (0x81) shall be
                expected after issuing this command.

                In case of an error, the error response will be returned.

        Opcode 0x06 - Connect L2CAP command

                Controller Index:       <controller id>
                Command parameters:     Address_Type (1 octet)
                                        Address (6 octets)
                                        PSM (2 octets)
                Response parameters:    <none>

                This command creates the L2CAP transport that will carry the

                error) shall be expected after issuing this command.

                In case of an error, the error response will be returned.

        Opcode 0x09 - SDP Discover command

                Controller Index:       <controller id>
                Command parameters:     Address_Type (1 octet)
                                        Address (6 octets)
                                        UUID (2 octets)
                Response parameters:    <none>

                This command generates an SDP service search on Address for the
                BIP service class given by UUID (see BIPImagingSvclass in
                autopts/pybtp/types.py: 0x111A Imaging, 0x111B Imaging
                Responder, 0x111C Imaging Automatic Archive, 0x111D Imaging
                Referenced Objects). The discovered RFCOMM Channel/L2CAP PSM
                and the BIP SDP record attributes (SupportedCapabilities,
                SupportedFeatures, SupportedFunctions) are returned
                asynchronously in the SDP Discovered Event (0xaa).

                In case of an error, the error response will be returned.

        Opcode 0x0a - Server Register command

                Controller Index:       <controller id>
                Command parameters:     Address_Type (1 octet)
                                        Address (6 octets)
                                        Conn_Type (1 octet)
                Response parameters:    <none>

                This command registers a local BIP OBEX server for the primary
                imaging connection associated with Address, so the IUT starts
                accepting incoming OBEX CONNECT requests. Conn_Type selects the
                primary connection role advertised by the server (see
                BIPConnType in autopts/pybtp/types.py, e.g. PRIM_IMAGE_PUSH=0,
                PRIM_IMAGE_PULL=1, PRIM_ADVANCED_IMAGE_PRINTING=2,
                PRIM_AUTO_ARCHIVE=3, PRIM_REMOTE_CAMERA=4,
                PRIM_REMOTE_DISPLAY=5). Once registered, incoming OBEX requests
                are signalled through the Server *_Req events (0x84-0x96); the
                test script answers each of them with the matching *_Rsp
                command.

                In case of an error, the error response will be returned.

        Opcode 0x0b - Server Unregister command

                Controller Index:       <controller id>
                Command parameters:     Address_Type (1 octet)
                                        Address (6 octets)
                Response parameters:    <none>

                This command unregisters the local primary BIP OBEX server
                previously registered with the Server Register command (0x0a)
                for Address.

                In case of an error, the error response will be returned.

        Opcode 0x0c - Client Connect command

                Controller Index:       <controller id>
                Command parameters:     Address_Type (1 octet)
                                        Address (6 octets)
                                        Conn_Type (1 octet)
                Response parameters:    <none>

                This command makes the IUT act as an OBEX client and send an
                OBEX CONNECT to the peer's primary BIP server identified by
                Address, over a transport already established with the Connect
                RFCOMM (0x03) or Connect L2CAP (0x06) command. Conn_Type
                selects the primary connection role being requested (see
                BIPConnType). The outcome is reported asynchronously in the
                Client Connected Event (0x97).

                In case of an error, the error response will be returned.

        Opcode 0x0d - OBEX Disconnect command

                Controller Index:       <controller id>
                Command parameters:     Address_Type (1 octet)
                                        Address (6 octets)
                Response parameters:    <none>

                This command makes the IUT, acting as an OBEX client, send an
                OBEX DISCONNECT for the primary session on Address. The outcome
                is reported asynchronously in the Client Disconnected Event
                (0x98).

                In case of an error, the error response will be returned.

        Opcode 0x0e - OBEX Abort command

                Controller Index:       <controller id>
                Command parameters:     Address_Type (1 octet)
                                        Address (6 octets)
                Response parameters:    <none>

                This command makes the IUT, acting as an OBEX client, send an
                OBEX ABORT for the ongoing primary operation on Address. The
                outcome is reported asynchronously in the Client Aborted Event
                (0x99).

                In case of an error, the error response will be returned.

        Opcode 0x0f - Connect Response command

                Controller Index:       <controller id>
                Command parameters:     Address_Type (1 octet)
                                        Address (6 octets)
                                        Rsp_Code (1 octet)
                                        Data_Length (2 octets)
                                        Data (Data_Length octets)
                Response parameters:    <none>

                This command is used by the test script, acting as the primary
                OBEX server, to answer an incoming OBEX CONNECT request
                signalled by the Server Connect Req Event (0x84). Rsp_Code is
                the OBEX response code (see OBEXRspCode in
                autopts/pybtp/types.py, e.g. 0xa0 SUCCESS). Data carries the
                OBEX headers/body to return with the response (see OBEXHdr in
                autopts/pybtp/types.py); typically only the Who header, echoing
                the target UUID from the request, is present.

                In case of an error, the error response will be returned.

        Opcode 0x12 - GetCapabilities command

                Controller Index:       <controller id>
                Command parameters:     Address_Type (1 octet)
                                        Address (6 octets)
                                        Final (1 octet)
                                        Data_Length (2 octets)
                                        Data (Data_Length octets)
                Response parameters:    <none>

                This command makes the IUT, acting as an OBEX client, send a
                GetCapabilities request (OBEX GET, Type header
                "x-bt/img-capabilities") to the peer's primary BIP server on
                Address. Final indicates whether this is the last request
                packet (1) or more request packets follow (0); Data carries the
                OBEX headers/body for this request (see OBEXHdr in
                autopts/pybtp/types.py). The peer's reply is reported
                asynchronously in the Client GetCapabilities Rsp Event (0x9a)
                rather than as a synchronous response; on an OBEX CONTINUE
                reply the IUT automatically issues the next continuation
                request.

                In case of an error, the error response will be returned.
